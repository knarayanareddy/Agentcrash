# Agentcrash — static review

## Scope and verdict

Pinned revision `1a80e2c7c53418a8ee1cdb5172f7b987d248be1e`: a hackathon **prototype**, not a production financial service. Its README explicitly says “no production authentication” and “Bind it to loopback” ([README:73–80](https://github.com/knarayanareddy/Agentcrash/blob/1a80e2c7c53418a8ee1cdb5172f7b987d248be1e/README.md#L73-L80)). The sampled code contains substantive policy and transaction mechanisms, but public exposure, identity, privacy, availability, recovery and payment readiness are not established.

This is a static, partial review. **Runtime NOT RUN:** no installation, application, tests, provider calls, browser, deployment, migration or restore. Middleware, ingress, other routes, full verifier and Python guard implementations were not traced. Conclusions about route-level code do not establish the effective network boundary.

## Architecture and product boundary

The Next POST handler parses input and invokes `processTicketLab` ([route:10–30](https://github.com/knarayanareddy/Agentcrash/blob/1a80e2c7c53418a8ee1cdb5172f7b987d248be1e/src/app/api/ticket-lab/route.ts#L10-L30)). The orchestrator obtains a proposal, then loads session state under a transaction lock ([ticket-lab:164–181](https://github.com/knarayanareddy/Agentcrash/blob/1a80e2c7c53418a8ee1cdb5172f7b987d248be1e/src/lib/ticket-lab.ts#L164-L181)). After fixture-based guard and judgment, it calls the dispatcher inside the transaction with a `commitMockRefund` callback that the dispatcher may invoke ([ticket-lab:192–258](https://github.com/knarayanareddy/Agentcrash/blob/1a80e2c7c53418a8ee1cdb5172f7b987d248be1e/src/lib/ticket-lab.ts#L192-L258)). Workpaper verification follows that call; session writes follow verification, and the enclosing transaction commits afterward ([ticket-lab:390–425](https://github.com/knarayanareddy/Agentcrash/blob/1a80e2c7c53418a8ee1cdb5172f7b987d248be1e/src/lib/ticket-lab.ts#L390-L425)). This is source tracing, not a successful transaction observation.

Separately, Pages serves a browser playground from `docs/`; its verdict logic directly combines guard and capability outcomes ([docs/app.js:88–106](https://github.com/knarayanareddy/Agentcrash/blob/1a80e2c7c53418a8ee1cdb5172f7b987d248be1e/docs/app.js#L88-L106)). The Python package exposes its own `saaf` CLI and subcommands ([pyproject:1–21](https://github.com/knarayanareddy/Agentcrash/blob/1a80e2c7c53418a8ee1cdb5172f7b987d248be1e/saaf-circuit-breaker/pyproject.toml#L1-L21)); it is not the Next server. PostgreSQL and optional proposal/judgment providers are external dependencies.

## Findings ledger

- **F01 — confirmed static; high conditional on exposure.** GET looks up a validated session ID and returns `...session`; POST calls processing without a route-level principal or owner check ([route:10–30](https://github.com/knarayanareddy/Agentcrash/blob/1a80e2c7c53418a8ee1cdb5172f7b987d248be1e/src/app/api/ticket-lab/route.ts#L10-L30), [route:44–56](https://github.com/knarayanareddy/Agentcrash/blob/1a80e2c7c53418a8ee1cdb5172f7b987d248be1e/src/app/api/ticket-lab/route.ts#L44-L56)). Session IDs alone are not authorization. The effective ingress/middleware boundary is unknown; if externally reachable, session data, state changes and provider spending are at risk. Establish identity and ownership before public use.
- **F02 — confirmed static; medium.** Pages workflow says “Rebuild the bundle after changing” policy modules but uploads `docs` without a build ([pages.yml:3–8](https://github.com/knarayanareddy/Agentcrash/blob/1a80e2c7c53418a8ee1cdb5172f7b987d248be1e/.github/workflows/pages.yml#L3-L8), [pages.yml:29–43](https://github.com/knarayanareddy/Agentcrash/blob/1a80e2c7c53418a8ee1cdb5172f7b987d248be1e/.github/workflows/pages.yml#L29-L43)). This creates drift risk, not proof the current bundle is stale. Build and compare in CI.
- **F03 — owner decision; high consequence.** The README calls the side effect a “mock ledger” and says “No external refunds” ([README:20–30](https://github.com/knarayanareddy/Agentcrash/blob/1a80e2c7c53418a8ee1cdb5172f7b987d248be1e/README.md#L20-L30), [README:130–137](https://github.com/knarayanareddy/Agentcrash/blob/1a80e2c7c53418a8ee1cdb5172f7b987d248be1e/README.md#L130-L137)). Human review is simulated; the seal is not a signature or certification. Real payments and accountable approval require a separate design and explicit approval.
- **F04 — historical CI; informational.** Snapshot metadata records `"conclusion": "success"` for [Pages deployment run 39454555142](https://github.com/knarayanareddy/Agentcrash/actions/runs/39454555142) at the pinned SHA. It does not prove Node/Python tests passed, the present served artifact matches, or deployment is suitable for production.
- **F05 — unverified availability risk; medium.** A transaction takes a session advisory lock and then executes `await judgeWithJev({` ([ticket-lab:177–181](https://github.com/knarayanareddy/Agentcrash/blob/1a80e2c7c53418a8ee1cdb5172f7b987d248be1e/src/lib/ticket-lab.ts#L177-L181), [ticket-lab:192–211](https://github.com/knarayanareddy/Agentcrash/blob/1a80e2c7c53418a8ee1cdb5172f7b987d248be1e/src/lib/ticket-lab.ts#L192-L211)). Provider latency may extend lock and connection occupancy; timeout behavior and concurrent load were not measured. Preserve atomicity while testing contention and failure.
- **F06 — confirmed static; medium product risk.** The Pages playground ends with `else verdict = "ALLOW";` without the judgment stage visible in the Next path ([docs/app.js:99–106](https://github.com/knarayanareddy/Agentcrash/blob/1a80e2c7c53418a8ee1cdb5172f7b987d248be1e/docs/app.js#L99-L106); [ticket-lab:216–245](https://github.com/knarayanareddy/Agentcrash/blob/1a80e2c7c53418a8ee1cdb5172f7b987d248be1e/src/lib/ticket-lab.ts#L216-L245)). It is a simplified local demonstration, not an equivalent end-to-end decision. Make this difference explicit and test it.
- **F07 — confirmed static; medium policy decision.** On `if (!response.ok)`, the client returns `offlineHeuristicProposal(fixture, customerMessage, Date.now() - start)` ([proposal-model:251–284](https://github.com/knarayanareddy/Agentcrash/blob/1a80e2c7c53418a8ee1cdb5172f7b987d248be1e/src/lib/proposal-model.ts#L251-L284)); authorization still depends on later guards and judgment. Whether automatic fallback should remain eligible for a mock commit is an owner decision; do not imply provider failure necessarily halts the whole flow.

## Five-discipline assessment

**Correctness/code.** Guard inputs come from fixture facts, while model amounts and evidence references are bounded ([ticket-lab:121–134](https://github.com/knarayanareddy/Agentcrash/blob/1a80e2c7c53418a8ee1cdb5172f7b987d248be1e/src/lib/ticket-lab.ts#L121-L134)). The intended ordering is meaningful; independent replay semantics, concurrency correctness and live provider behavior remain unverified.

**Automation/testing.** The dispatcher test checks non-ALLOW verdicts with a spy and `runnerCalls.length` zero ([capability-dispatch.test.ts:86–102](https://github.com/knarayanareddy/Agentcrash/blob/1a80e2c7c53418a8ee1cdb5172f7b987d248be1e/tests/capability-dispatch.test.ts#L86-L102)). Ticket Lab tests stub outbound fetch and assert mock-only results ([ticket-lab.test.ts:30–68](https://github.com/knarayanareddy/Agentcrash/blob/1a80e2c7c53418a8ee1cdb5172f7b987d248be1e/tests/ticket-lab.test.ts#L30-L68), [ticket-lab.test.ts:126–152](https://github.com/knarayanareddy/Agentcrash/blob/1a80e2c7c53418a8ee1cdb5172f7b987d248be1e/tests/ticket-lab.test.ts#L126-L152)). Their presence is not a pass result. Separate Python and Node gates and real transaction tests remain to be observed.

**DevOps/operations.** `DATABASE_URL` is required for the pool ([db/index.ts:5–19](https://github.com/knarayanareddy/Agentcrash/blob/1a80e2c7c53418a8ee1cdb5172f7b987d248be1e/src/db/index.ts#L5-L19)); migration safety, isolated test data, backup/restore, resource budgets and release rollback are unverified. The manifest declares Node scripts and a lockfile is in the snapshot tree; Python declares lower bounds ([package.json:4–13](https://github.com/knarayanareddy/Agentcrash/blob/1a80e2c7c53418a8ee1cdb5172f7b987d248be1e/package.json#L4-L13), [pyproject:6–14](https://github.com/knarayanareddy/Agentcrash/blob/1a80e2c7c53418a8ee1cdb5172f7b987d248be1e/saaf-circuit-breaker/pyproject.toml#L6-L14)). Dependency integrity and current advisories were not checked; README audit figures are historical claims, not our results.

**OWASP/security.** F01 covers authentication and authorization. Customer text is explicitly untrusted in the provider prompt ([proposal-model:81–102](https://github.com/knarayanareddy/Agentcrash/blob/1a80e2c7c53418a8ee1cdb5172f7b987d248be1e/src/lib/proposal-model.ts#L81-L102)); injection containment still needs adversarial end-to-end tests. The configurable provider base receives a bearer key ([proposal-model:256–270](https://github.com/knarayanareddy/Agentcrash/blob/1a80e2c7c53418a8ee1cdb5172f7b987d248be1e/src/lib/proposal-model.ts#L256-L270)): restrict who can configure it and verify credential-to-host binding. Retention, output escaping, log redaction and provider data handling are unverified, not confirmed leaks.

**UI/UX/accessibility.** Static playground and Next interface are distinct products (F06). The playground writes a bundle-load failure message ([docs/app.js:1–10](https://github.com/knarayanareddy/Agentcrash/blob/1a80e2c7c53418a8ee1cdb5172f7b987d248be1e/docs/app.js#L1-L10)); keyboard operation, focus, status announcements, visual contrast and error handling were not exercised. The Python CLI also needs understandable errors and exit codes; it is not a web UI.

## Production blockers, questions and evidence limits

Owner must decide audience and ingress, identity/ownership, permitted providers and credential custody, retention, cost caps, hosting, release/restore ownership, whether fallback may authorize mock actions, and whether any real payment or human approval integration is intended. Synthetic policy requires domain review before real use. No certification is asserted.
